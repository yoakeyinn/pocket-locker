# CLAUDE.md

Guidance for Claude Code when working in this repository.

**Pocket Locker**: an Expo / React Native app that opens a pedestrian door and a garage gate over Bluetooth, talking to an ESP32 that drives two relays. Identifiers, UI texts and docs are in Spanish; this file is in English. Stack: Expo SDK 58, RN 0.88 (new architecture, Hermes), expo-router, twrnc (Tailwind for RN), zustand, Jest 30 (`jest-expo`) + `@testing-library/react-native`.

## Commands

- `npm start` — Expo dev server. `npm run android|ios` for a native build. There is no web target (no Bluetooth there).
- `npm test` — all tests. One file: `npx jest tests/services/ErrorService.test.ts`; one test: add `-t "<name>"`. Type-check: `npx tsc --noEmit` (errors under `tests/` about `jest` globals are expected noise; add `--noUnusedLocals` to find dead imports).
- `npm run simular [-- --dev-client --tunnel] [--sin-vincular] [--bluetooth-apagado]` — runs the app with a **simulated Bluetooth device** (no ESP32; works in Expo Go) to review every screen. See "Simulation".
- Real Bluetooth needs a native dev build (`npx expo prebuild`, then `npx expo run:android`/`run:ios`); Expo Go has no BLE/Classic modules. EAS profiles in `eas.json`: `development`, `preview` (APK), `production`.
- ESP32 firmware: open `esp32/` in PlatformIO, `pio run -t upload` (env `esp32dev`, `src_dir = .`, so `esp32/main.cpp` is the whole firmware).
- Bump the version **only in `package.json`** (`app.config.js` version/runtimeVersion and `APP_VERSION` in `src/styles/styles.ts` read it).

## Map of the code

- `index.js` — runtime polyfills (DOMException, PerformanceObserver), then `expo-router/entry`.
- `src/app` (every file is a route — never put tests or helpers here): `_layout` (fonts, providers, error boundary), `index` (**splash**; `/` needs an `index` file), `nombre`, `buscar`, `puertas` (main screen), `ajustes`.
- `src/components`: shared UI — `Boton`, `BotonIcono`, `Campo`, `Aparece`, `Cargando`, `Estrella`, `Modal` (+ `ModalHost`, `mostrarModal`), `LimiteDeErrores`, `SinDispositivoCard`. UI used by one screen lives in a folder named after it (`buscar/`, `puertas/`).
- `src/services`: `BluetoothService.tsx` (transports + zustand store + provider), `StorageService.ts` (`LogService`, `CryptoService`, `StorageService`, `esPinValido`), `ErrorService.ts` (fatal-error pipeline), `comun.ts` (shared types/constants, `parsearPin`/`esPinValido`, `esLocker`, `modoSimulacion`).
- `src/styles`: `styles.ts` (twrnc `tw`, `Colors`, `tipografia`, `cicloPulso`, splash styles/animations), `tipografia/` (fonts + `Text`/`TextInput` wrapper), `i18n/` (literals).
- `tests/` mirrors `src/` (`app`, `components`, `services`, `styles`) plus `simulacion/` (the Bluetooth simulation and its launcher). `tailwind.config.js` defines the palette; `app.config.js` is the dynamic Expo config.

Navigation: splash → `nombre` while there is no user name (asked once, saved with `guardarNombreUsuario`, then continues) → `puertas` if a locker is paired, else `buscar`. `puertas` is the root (system back leaves the app); without a paired device it shows `SinDispositivoCard` instead of the door buttons. `ajustes` only has the paired-device card (rename, connect/disconnect, unlink → `buscar`); theme/icon/app-lock were removed because they were never applied — reintroduce them together with their implementation.

## Bluetooth and protocol

- `BluetoothService` is a singleton hiding two transports behind one API: BLE GATT (`react-native-ble-plx`, Nordic UART UUIDs; base64 via global `atob`/`btoa`, commands are ASCII) and Bluetooth Classic SPP (`react-native-bluetooth-classic`). State is in the zustand store `usePocketStore`; `BluetoothProvider` / `useBluetooth` handle AppState, permissions and reconnects. `cargando` is true until the stored device has been read.
- **Wire protocol** (`esp32/main.cpp`): line-based text. The firmware supports a challenge flow (`PLK:REQ_CHALLENGE` → nonce valid 15 s → `PLK:AUTH:<HMAC_HEX>:<CMD>`, HMAC-SHA256 over `"<nonce>:<cmd>"` keyed with the PIN) and a direct form `PLK:<PIN>:<CMD>`. **The app only uses the direct plaintext-PIN form** (`enviarComando`); `CryptoService` is tested but never called. Pulse 5 s + 5 s cooldown (README says 1 s/2 s: outdated); failed auth only adds a growing delay. Relays: GPIO 26 garage, GPIO 27 door; Bluetooth name `PLBT`. Do not treat any of this as a security boundary.
- **PIN / access codes** (`parsearPin` in `comun.ts`, returns `{ esValido, peatonal, garaje, dias }`): `2415` (`DEFAULT_SECURITY_PIN`) is the administrator and opens both doors; a user code `2S0BP<p>G<g>[dd]` authorises the pedestrian door (`p`) and/or the garage (`g`) with 1/0 (not both 0) and optionally expires after `dd` days (1–99; the phone only displays it, the ESP32 enforces). `esPinValido` = `parsearPin(...).esValido`. The code the user types when pairing is stored as the device PIN (SecureStore) and is what `puertas` reads from `devicePin`: only the authorised doors are shown (one door → a label instead of tabs, no swipe/dots) and a temporary code shows "Acceso temporal: n día(s)"; an unrecognised stored code does not restrict anything. It must **never be shown to a normal user** nor logged (`enmascarar()` turns `PLK:<PIN>:P` into `PLK:***:P`); only the simulation shows it (`*_simulacion` literals).
- **What is a locker**: `esLocker(dispositivo)` in `comun.ts` — Bluetooth name contains PLBT, POCKET LOCKER or ESP32. The radar auto-detects with it and the manual pairing modal refuses any other device (real app and simulation alike).
- `app.config.js` also holds a plugin that patches the Android manifest (drops `maxSdkVersion` on legacy BLUETOOTH perms, `neverForLocation` on BLUETOOTH_SCAN, location perms ≤ API 30) and `withBuildConfigEnabled`: AGP 8+/9 no longer generates `BuildConfig` for libraries, and `react-native-bluetooth-classic` (unmaintained) needs it, so the plugin appends `buildFeatures.buildConfig = true` for all subprojects at prebuild (fixes the EAS `cannot find symbol BuildConfig` failure).

### Native-call pitfalls (they crash the app and cannot be caught from JS)
- `pedirActivar`: `requestBluetoothEnabled` fires an intent with no native try/catch — no adapter throws `ActivityNotFoundException`, no permission (Android 12+) throws `SecurityException`. So it checks `isBluetoothAvailable()` and `tienePermisos()` first; other native calls (`getBondedDevices`, `vincularDispositivo`, `cancelarDescubrimiento`) are guarded likewise. Automatic calls (AppState → active) must use `pedirActivar(false)` so they never open system settings.
- Settings screens: `expo-intent-launcher` is an Expo module (not in `NativeModules`); `abrirAjusteAndroid` loads it lazily with `require` and falls back to `Linking.openSettings()`.

## Screens and flows

- **Splash (`src/app/index.tsx`)**: 3 s is a *minimum*. The exit fade (+0.25 s) starts only when the animation is done, `cargando` is false and the startup Bluetooth check has finished. That check never shows anything on the splash: if the device supports Bluetooth (`esSoportado()`, false in Expo Go) and it is off, the "Bluetooth apagado" modal is shown right after `router.replace`, i.e. on the next screen. "Ir a Ajustes" opens Bluetooth settings; "Encender" calls `solicitarPermisos()` **then** `pedirActivar()` (without permissions, not yet requested on a first launch, `pedirActivar` does nothing). No startup-task registry on purpose: for a future login/session check expose a loading flag from its own provider (like `cargando`) and add it to the exit condition.
- **`nombre`**: first-run screen (title, help, `Campo` + `Boton`); an empty name shows `tipografia.error` under the field. `Campo` (`src/components/Campo.tsx`) is the shared label + input + error (testIDs `input-<id>`, `error-<id>`; red border with error), also used by the pairing modal.
- **`buscar`**: starts with the radar auto-search, which only *checks* permissions (`tienePermisos`); if missing it shows the explainer and the system dialog appears only on "Conceder permisos" (the 15 s timer is cleared there too). With Bluetooth off the auto-search falls back to the manual list. When a locker is detected, 1 s later a `Modal` asks for confirmation (a `mostrarModal` wrapped in a promise); cancelling goes to the manual list. If the 15 s limit passes with nothing detected it also falls back to the manual list.
- **Manual list (`DeviceDiscoveryListView`)**: title, help text, "Buscar de nuevo" + radar buttons, the list, and `AvisoNoAparece` (the "¿No aparece tu Pocket Locker?" help card with the only "Abrir ajustes Bluetooth" button) **pinned to the bottom, always visible**. The list shows 2–3 rows (`filasVisibles`, from the free height measured with `onLayout` and the real height of the first row) and a discreet "Ver más (n)" / "Ver menos" text button; with no results and no search running it shows "No se han encontrado dispositivos." Pull-to-refresh uses the normal native `RefreshControl` (black on white) — do not hide it or stack a custom spinner on it.
- **Pairing modal (`ModalVincularDispositivo`)**: errors never open extra modals. Empty/wrong PIN → `tipografia.error` text under the PIN input; device that is not a locker → `pl_vinculacion_error_mac`, any other pairing failure → `pl_vinculacion_error_generico`, both under the name input; the offending input gets a red border. Errors clear on edit or when reopened. Order of checks: PIN empty → PIN valid → `esLocker` → pair. Auto-pairing (radar) and manual pairing share `vincularYEntrar` in `buscar.tsx`.

## UI rules

- **Palette**: six colors only — `black`, `white`, `beige` (`#FAF8F2`, backgrounds), `gray` (`#444444`), `silver` (`#D4D4D4`) and `red` (`#5a0505`). Defined once in `tailwind.config.js` (it *replaces* Tailwind's colors; `app.config.js` reads splash/icon colors from it). Use classes (`bg-beige`) or `Colors.black` for color props; never hex. `tests/styles/paleta.test.ts` enforces it. Doors are told apart by shade (pedestrian black, garage gray).
- **Red** is used only for: the fatal-error modal title, the "Desvincular dispositivo" button in `ajustes`, field errors (`tipografia.error` + red input border) and the status colors in `puertas`. **No modal button is ever red** (even `style: 'destructive'`; tested).
- **Typography**: Playfair Display for titles (`font-display`), Inter for the rest, loaded in `_layout` via `useFonts` (`fuentesArchivos.ts`). Always import `Text`/`TextInput` from `src/styles/tipografia/Tipografia`, never from `react-native`: the wrapper maps `font-bold` etc. to the per-weight font file (Android needs one file per weight and `fontWeight: 'normal'`; see `fonts.ts`). Fonts live in `assets/fonts/<family>/` with their OFL `LICENSE.txt`; to add a weight copy the `.ttf` and register it in `fuentesArchivos.ts` and `fonts.ts`. Without fonts the system font is used.
- **Registered text styles (`tipografia` in `styles.ts`)**: `titulo` (Playfair italic bold, add size where used), `texto` (Inter light 14 px, wide tracking, black — buttons), `anotacion` (same as `texto`, gray — taglines, fine print), `error` (11 px, tighter tracking, red, right-aligned under its input). Use them (`style={[tipografia.texto, ...]}`) instead of retyping classes.
- **`Boton`**: the only button (also used inside `Modal`): `rounded-lg`, black border, `tipografia.texto`; `relleno` = black with white text, `compacto` = lower, optional `icono`, `cargando` swaps the icon for `Cargando`. Radar/permissions/list/empty states all use it.
- **`Cargando`**: the only loading indicator — the unlit splash star (silver) spinning very slowly (8 s/turn). `ActivityIndicator` is banned (a test scans `src`).
- **`Aparece`**: soft fade-and-rise entrance (700 ms, optional `retraso`, `retrasoEscalonado(i)` for lists) shared with the splash/radar. Use it for blocks that enter a screen.
- **`Estrella`**: every star (splash bar, radar, `Cargando`) is this component, drawing FontAwesome6 `star` (the roundest bundled icon). The glyph is 1.125 em wide, so `Estrella` divides `tamano` by 1.125 to fit a square box. Colors: unlit `ESTRELLA_APAGADA` (silver), lit `ESTRELLA_ENCENDIDA` (black). The radar's orbiting stars are unlit; the found one is lit.
- **`Modal`** (`src/components/Modal.tsx`): the only dialog style — beige card, Playfair title, light message, optional `children`, `izquierdo` outlined / `derecho` filled, `onCerrar` for the Android back button. The entrance is approved and fixed (`ANIMACION_MODAL`: 120 ms delay, 700 ms `ease`, 10 px rise, 0.97→1 scale, native driver); `tests/components/modales.test.ts` fails if it changes, if `Alert.alert` is used or if RN's `Modal` is imported elsewhere. **Never use `Alert.alert`**: call `mostrarModal(titulo, mensaje?, botones?)` (same button shape; first button left, last right, `style: 'cancel'` = back button). `<ModalHost />` is mounted once in `_layout`; tests that need the real dialog render it next to the screen (or `jest.mock` the module). One modal at a time: a new one replaces the previous.
- **Responsive**: the splash scales with `splashMedidas(ancho, alto)` (factor min(w/390, h/800) clamped 0.8–1.35); the radar and the manual list use `useWindowDimensions` (radar square = min(288, width−64, 40 % height); titles sized from the width). Don't hardcode pixel sizes on these screens. Letter spacing that depends on a runtime font size is inline: twrnc `tracking-*` classes warn without a `text-*` size in the same `tw` call.
- **Animation gotchas**: a view cannot mix native-driver values (transform/opacity) with JS-driver ones (`width`/`left`) — keep each on its own parent/child view. The native driver ignores `easing` in `interpolate`, so apply the easing in the master `Animated.timing` and interpolate linearly. Splash title: single line + `self-stretch` + `adjustsFontSizeToFit` (the wide-tracked italic was clipped on Android).
- **Splash icon**: `assets/splash-icon.png` is derived from `assets/icon.png` (background made transparent, cropped square, 512 px); regenerate it if `icon.png` changes, never touch `icon.png`.

## Errors and logging

- `reportarErrorFatal(error, contexto)` (`ErrorService.ts`) logs `[FATAL]` and opens the same `Modal` via `mostrarModalError`: red title "Algo ha salido mal", left button "Ver logs/Ocultar logs" unfolds the report (selectable, copy icon via `expo-clipboard` loaded lazily with a `Share` fallback — needs a rebuilt dev build), right button "Cerrar" exits the app (`BackHandler.exitApp()`, Android only; iOS cannot). While it is open, `mostrarModal` ignores every call. Use it only for failures with no way forward, never for retryable errors.
- Triggers: `instalarCapturaDeErrores()` (global `ErrorUtils` handler: fatal exceptions open the modal; non-fatal exceptions and unhandled promise rejections via Hermes' tracker are only logged) and the `LimiteDeErrores` boundary (render errors). `_layout` is `SafeAreaProvider` → `LimiteDeErrores` → `Aplicacion` (fonts, `BluetoothProvider`, router) with `<ModalHost />` as a **sibling** of the boundary so the modal survives any crash. The modal must be the only thing on screen: `LogBox.ignoreAllLogs(true)`, the previous handler is not called. Native crashes cannot be caught.
- `construirInforme` builds the report: version, platform, store snapshot, error + stack/cause, context and the last 120 `LogService` entries.
- **`LogService.error` prints with `console.log`, never `console.error`**: RN forwards `console.error` to the global handler as a non-fatal exception, which would log again in a loop.
- **Logging rule**: no `catch` may swallow an error silently — `LogService.warn/error('[Zona] qué falló', error)`; log the main steps of each flow with `LogService.info`.

## Literals (i18n)

Texts live in `src/styles/i18n/locales/es.json` and `en.json` (flat keys prefixed `pl_`; `pl_app_titulo` first, the rest alphabetical; same keys **and same `{{marcadores}}`** in both — tested) and are read with `t('pl_clave', { marcador })`. A literal embedding a value must be a whole sentence with a marker in the JSON — never concatenate or interpolate in code (word order differs per language). Fully migrated: `buscar` (including the service errors it can show), `SinDispositivoCard`, splash, error modal. Still Spanish in code: most of `puertas`, `ajustes`, the rest of `BluetoothService` error messages. For plurals/dates/rich text move to `i18next` + `expo-localization` (same `{{x}}` syntax).

## Simulation (`npm run simular`)

Sets `EXPO_PUBLIC_SIMULAR_BT` (comma list) and clears the Metro cache. `_layout` then calls `instalarSimulacion` from `tests/simulacion/bluetooth.ts`, which replaces `BluetoothService` methods with fakes: adapter on, permissions granted, instant pairing, connect ≈0.9 s, commands answer `OK:SIMULADO`, and `listarDispositivos` finds **seven devices** (`DISPOSITIVOS_SIMULADOS`: decoys at 3/5/7 s, the `PLBT` — 4th — at 10 s, three more decoys right after) so the radar detection and the "Ver más" list can be reviewed. The fake does **not** validate anything: decoys are rejected by the app's own `esLocker` check. Unless `--sin-vincular`, `StorageService.obtenerDispositivo` returns a paired demo locker when none is stored; `--sin-vincular` has no saved name, so it starts in `nombre` and then goes to `buscar`; `--bluetooth-apagado` starts with the adapter off (turns on after `pedirActivar` or opening settings; "Ir a Ajustes" opens the real settings in a dev build, "Encender" only flips the fake adapter). Flags combine. Without the variable nothing is patched. `modoSimulacion()` (`comun.ts`) is the single place that reads it.

## Tests

- Jest, files in `tests/` mirroring `src/`. Use `await render(...)` and wrap `fireEvent` in `await act(async () => ...)` when it changes state.
- Tests that `jest.mock('react-native')` without `Animated` (e.g. `ajustes`) must also mock `Aparece` and `Cargando`. Tests importing `BluetoothService` (even via `BuscarComponents`) need `@react-native-async-storage/async-storage`, `react-native-bluetooth-classic` and `react-native-ble-plx` mocked.
- Guard tests worth knowing: `paleta` (no colors outside the palette), `modales` (modal rules), `Cargando` (no `ActivityIndicator`), `Modal` (no red button), `i18n` (same keys/markers).
